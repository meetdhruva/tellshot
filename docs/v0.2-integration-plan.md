### 1.5 MCP: one `Context`, one `serve`

The branches produced three signatures: `serve(in, out, &Sandbox)` + private `Session` with an

```rust
pub(crate) type EngineFactory = fn() -> Result<Box<dyn OcrEngine>, CliError>;

/// What one MCP session may touch. Built once in `main`, borrowed by every call.
#[derive(Debug)]
pub(crate) struct Context {
    pub(crate) sandbox: Sandbox,
    /// Library folder; `None` when started with `--no-library`.
    pub(crate) library: Option<PathBuf>,
    /// Destinations file from `--config` / `TELLSHOT_DESTINATIONS`; `None` reads settings.toml.
    pub(crate) destinations: Option<PathBuf>,
    ocr_factory: EngineFactory,
    ocr: OnceLock<Result<Box<dyn OcrEngine>, CliError>>,
}
impl Context {
    pub(crate) fn new(sandbox: Sandbox) -> Self;              // library None, default factory
    pub(crate) fn with_library(self, dir: Option<PathBuf>) -> Self;
    pub(crate) fn with_destinations(self, file: Option<PathBuf>) -> Self;
    pub(crate) fn with_ocr(self, factory: EngineFactory) -> Self;   // tests: FakeEngine
    fn library(&self) -> Result<&Path, CliError>;
    fn engine(&self) -> Result<&dyn OcrEngine, CliError>;
}
pub(crate) fn serve(input: impl BufRead, output: impl Write, context: &Context)
```

### 1.7 API mismatches between branches (fix in WP0 unless noted)

1. **Two config roots and two library paths (real bug on every OS).** *library* CLI uses
   `dirs::data_dir()/Tellshot/library`; *platform* `Paths::library_dir()` is
   `data_local_dir()/Tellshot/library` (differs on Windows: Roaming vs Local). *share* CLI reads
   `<config>/tellshot/destinations.toml` (lowercase, hand-rolled lookup); *platform* stores
   `[sharing.destinations.<name>]` in `<config>/Tellshot/settings.toml` as raw `toml::Value`.
   **Resolution:** `tellshot_settings::Paths::discover()` is the only source of paths. CLI default
   library = `paths.library_dir()`. `destinations::load(file, name)`: with `--config` read that
   file's `[destinations.*]`; otherwise load settings and convert
   `settings.sharing.destinations[name]` with `toml::Value::try_into::<tellshot_share::Destination>()`.
   Delete `destinations::config_dir`/`default_path`. Nothing shipped, so no migration.
2. **`CaptureError::Cancelled`** exists only on *platform*; *share*'s `RecordError::Capture(c) =>
   c.into()` picks up the new mapping automatically. No code change beyond 1.3.
3. **Recording and scrolling capture cannot work on the Wayland portal backend.** `CaptureSource`
   calls `backend.capture()` per frame; the portal backend makes one D-Bus Screenshot call (and
   possibly a dialog) per frame. Add to `tellshot-capture` (WP1):
   ```rust
   #[derive(Debug, Clone, Copy, PartialEq, Eq)]
   pub struct Capabilities { pub windows: bool, pub cursor: bool, pub streaming: bool,
                             pub interactive_pick: bool }
   trait CaptureBackend { fn capabilities(&self) -> Capabilities; /* default: all false */ }
   ```
   x11/xcap/synthetic: `windows`, `cursor`, `streaming` true. portal: only `interactive_pick`.
   `ops::record` and the app refuse `streaming == false` with `CaptureUnavailable` and the hint
   "recording on Wayland needs the ScreenCast portal, planned for 0.3; log into an X11 session".
4. **`Target.app_name`** (platform) has no consumer yet. Use it for `NewItem.source`
   (`app_name` else `name`) and `FileNameContext.app`.
5. **OCR `TextLayout` vs library `ItemMeta.ocr_text: Option<String>`.** The library stores text
   only, capped at `MAX_OCR_CHARS`. Store `layout.text()` truncated on a char boundary; do not
   persist word boxes (copy-text re-runs OCR, which is fast and keeps the index small). Add
   `privacy.index_text: bool` (default `true`, `#[serde(default)]`) to settings so indexing can
   be turned off.
6. **Library vs format 2.0.** `Library::add/save_project` go through `Project::save`, so items
   become 2.0 with no change; `INDEX_VERSION` is independent. Run `cargo test -p tellshot-library`
   after the merge: any test that pins project bytes or a rendered-text hash must be re-blessed
   deliberately, not loosened.
7. **Library single-writer lock vs a long-running app.** A `Library` holds the OS lock for its
   lifetime; an app that keeps one open makes every CLI write fail with exit 9. The app opens a
   writer per operation on a worker thread and drops it (section 2.4).
8. **Three resamplers.** `imaging::resample::resize` (library), `record::scale::resize`,
   `ocr::prepare::upscale`. After the merge switch `record` to `tellshot_imaging::resample::resize`
   and delete its private copy; leave `ocr::prepare` (integer upscale, different purpose).
9. **`Fonts` API moved** (*annotate*: `from_data`, `from_files`, `measure`; `none`, `system`,
   `from_bytes` kept). All other branches use only the kept functions (verified).
10. **`Shape` matches.** *text* constructs `Shape::{Redact,Rectangle,Highlight,Step,Arrow,Text}`
    whose fields are unchanged; it compiles. Any non-wildcard `match` on `ShapeKind` added by other
    branches needs the three new arms (the compiler finds them).
11. **Settings model gaps** for the product goal (add in WP0, all `#[serde(default)]`):
    `Action::PickColor`, `Action::Measure` (appended to `Action::ALL`, unbound in every preset),
    `privacy.index_text`, `capture.record_format: "gif" | "mp4"` (default gif), `capture.record_fps`.
    "Last region" is state, not a setting: it lives in `<data>/state.json` (section 2.4).
12. **IPC wording.** The *platform* docs say `tellshot-editor a.png`; the binary is renamed
    (D1). `Request::Capture` (v0.1) stays for wire compatibility; the app answers it by treating it
    as `Invoke{capture}` with `then=save`.

## 2. App architecture

### 2.1 One process, one binary: `tellshot-app`

**Decision.** `apps/editor` becomes `apps/app` (package `tellshot-app`, lib `tellshot_app`, binary
`tellshot-app`; Windows `tellshot-app.exe`, never `Tellshot.exe`, which would collide with the
CLI `tellshot.exe` on case-insensitive file systems). It hosts the tray, hotkeys, overlay, editor,
library, settings, recorder, pins and thumbnail on **one Slint event loop**. The CLI `tellshot`
stays a separate, GUI-free binary.

Why one process:

- Slint windows must live on the thread that runs the event loop, and the tray
  (`SystemTrayIcon`) needs that loop too. A second GUI process would need its own loop, its own
  settings watcher and a second IPC protocol for "open this capture in the editor". v0.1's ADR
  sketched agent + editor processes; with a native tray element in Slint that split buys only
  crash isolation, which autosave (2.8) covers more cheaply.
- Capture → overlay → editor hand-off stays in memory (`Arc<Image>`), which is what makes the
  ten-second loop feel instant. No PNG round trip, no pixels on a socket (`MAX_FRAME_BYTES` is
  1 MiB by design).
- One Slint compile, one `Theme`, one accessibility test harness.

Cost: a panic in editor code takes the tray down. Mitigation: `panic = "unwind"` is already set;
`main` wraps `run()` and relaunches once with `--recovered`; autosave restores documents.

### 2.2 Slint facts this design relies on

All verified in the 1.18.1 sources unless marked.

- `SystemTrayIcon` is a top-level element (`component Tray inherits SystemTrayIcon { Menu { … } }`)
  behind `slint/system-tray`; implemented with AppKit on macOS, Win32 on Windows, `ksni`
  (StatusNotifierItem over D-Bus) on Linux/BSD. The menu is reactive (`for` works), so
  "Recent captures ×5" is a model. It does **not** share globals with windows. GNOME needs the
  AppIndicator extension to show any tray icon (Ubuntu ships it); without it the app still works
  through hotkeys, deep links and a second launch (which opens the library window).
- With no window open the loop must be started with `slint::run_event_loop_until_quit()`.
- `Window` has `no-frame`, `always-on-top`, `full-screen`, `background`; `Window::set_position`,
  `set_size`, `take_snapshot` exist. Slint's `full-screen: true` maps to
  `Fullscreen::Borderless(None)`, i.e. "the monitor the window is on": it cannot name a monitor.
- `slint/unstable-winit-030` gives `slint::winit_030::WinitWindowAccessor`
  (`with_winit_window`, `on_winit_window_event`) and
  `BackendSelector::{with_winit_window_attributes_hook, with_winit_event_loop_builder,
  with_winit_custom_application_handler}`. We need it for: per-monitor fullscreen
  (`Fullscreen::Borderless(Some(monitor))`), `set_simple_fullscreen` (macOS), `with_skip_taskbar`
  (Windows), `with_active(false)` (thumbnail must not steal focus), `set_content_protected`
  (recorder bar invisible to capture on Windows/macOS), `drag_window` (pins),
  `with_activation_policy(Accessory)` (macOS). The feature is unstable by name: pin
  `slint = "~1.18"` and treat a Slint minor bump as a task, not a `cargo update` (D8).
- The attributes hook is one global closure with no window identity. Pattern: a thread-local
  `NEXT_KIND: Cell<WindowKind>` set immediately before `show()` (winit windows are created
  lazily on first show); the hook reads and resets it. Lives in `shell/windows.rs`, nowhere else.
- winit 0.30 has **no** runtime `set_activation_policy`, no "open file/URL" event on macOS, no
  wlr-layer-shell, no window positioning on Wayland (`set_outer_position` is a no-op there), and
  no OS drag-out. Each gap is handled below.
- Renderer is `renderer-software`. Transparent windows are only wired up on macOS in the winit
  adapter, so **no design below depends on window transparency**.
- `i-slint-backend-testing` can be initialised once per process: one scenario per test binary.

### 2.3 Threads

| Thread | Owns | Talks to the UI by |
|---|---|---|
| main | Slint loop, every window, `App` (`Rc<RefCell<…>>`), hotkey manager, tray | direct |
| capture worker (1, long-lived) | `Box<dyn CaptureBackend>` (it is `Send`, methods take `&mut`) | channel in, `invoke_from_event_loop` out |
| job pool (2 threads) | OCR, upload, library writes, thumbnails, export, hooks | same |
| recorder (owned by `tellshot-record`) | its own backend from `detect()` | `RecordingHandle` polled by a 250 ms `slint::Timer` |
| IPC (owned by `tellshot-ipc::ServerHandle`) | socket | handler posts `Event::Ipc`, answers `Done` at once |
| clipboard | one `arboard::Clipboard` for the process lifetime | channel in |
| portal shortcuts (Wayland only) | ashpd session | `invoke_from_event_loop` |

Rule: nothing blocks the main thread longer than a frame. Rule: no Slint type crosses a thread;
pixels cross as `Arc<tellshot_imaging::Image>` and become `slint::Image` on the main thread.

### 2.4 The core: a pure state machine

To keep "behaviour in Rust with unit tests, `.slint` is layout only", the app is split into a
pure core and a thin shell:

```rust
// apps/app/src/agent.rs: no Slint, no threads, no I/O. Fully unit-tested.
pub struct Agent { /* settings, capabilities, flow state, last region, recents */ }
impl Agent {
    pub fn new(settings: Settings, caps: Capabilities, state: PersistedState) -> Self;
    pub fn handle(&mut self, event: Event) -> Vec<Effect>;
    pub fn tray(&self) -> TrayModel;
}
```

`app.rs` is the only module that owns both the `Agent` and windows: it feeds events in and
performs effects (show a window, spawn a job, set the clipboard). Jobs go through

```rust
// jobs.rs
pub trait Spawner {
    /// Runs `job` off the UI thread and delivers its event back on the UI thread.
    fn spawn(&self, name: &'static str, job: Box<dyn FnOnce() -> Event + Send>);
}
pub struct ThreadSpawner { /* pool + invoke_from_event_loop */ }
pub struct InlineSpawner { /* tests: runs at once, queues the event; `pump()` delivers */ }
```

so the complete loop (hotkey → frames → overlay → confirm → clipboard + library + thumbnail) runs
deterministically in a test with `BackendChoice::Synthetic`, `tellshot_ocr::FakeEngine`,
`MemoryClipboard`, a temp `Paths::in_dir` and `InlineSpawner`.

`PersistedState` (`<data>/state.json`, written with `atomic_write`): `last_region`, `last_mode`,
`window positions`, `onboarding practice done`. Library access: `library::with_writer(&paths,
|lib| …)` opens, runs, drops (releases the lock); reads use `Library::open_read_only`.

### 2.5 Global hotkeys

```rust
// hotkeys.rs
pub trait HotkeyBackend {
    fn kind(&self) -> HotkeyBackendKind;                 // Native | Portal | Unavailable
    /// Replaces all bindings. One outcome per requested binding, in order.
    fn apply(&mut self, bindings: &[(Action, Hotkey)]) -> Vec<BindOutcome>;
}
pub enum BindOutcome { Bound, InUse { by: Option<String> }, Reserved { why: &'static str },
                       Unsupported }
pub fn detect(on_action: impl Fn(Action) + Send + Sync + 'static) -> Box<dyn HotkeyBackend>;
```

- **Windows, macOS, X11:** `global-hotkey` 0.10 (MIT/Apache; `RegisterHotKey`, Carbon
  `RegisterEventHotKey`, `XGrabKey`). The manager is created on the main thread (required on
  Windows and macOS). `settings::Key::code()` already returns the W3C code string that crate
  parses. A failed registration is `InUse`.
- **Wayland:** xdg-desktop-portal GlobalShortcuts through `ashpd` (`global_shortcuts` feature;
  KDE Plasma 6, GNOME 48+, Hyprland). We send ids (`Action::key()`), labels and preferred
  triggers; the desktop shows its own binding dialog and owns the final keys, so the Shortcuts
  page shows "Managed by your desktop" with an "Open shortcut settings" button.
- **No portal (older GNOME, wlroots without it):** `Unavailable`. Settings and onboarding show
  copyable commands to bind in the desktop's own keyboard settings:
  `tellshot-app "tellshot://capture?mode=region"`. A second launch only connects to the socket
  and exits, so this path costs a few milliseconds.

Conflict detection is three layers, all surfaced inline on the Shortcuts page and in onboarding:
`Shortcuts::conflicts()` (two actions, one key), `Hotkey::os_reserved(platform)` (known OS
claims), `BindOutcome::InUse` (another app).

**Windows 11 Print Screen.** Windows binds bare PrtSc to Snipping Tool when
`HKCU\Control Panel\Keyboard\PrintScreenKeyForSnippingEnabled` is 1 (default on current builds),
and then `RegisterHotKey` for it fails or never fires. Onboarding reads the value (read-only),
explains it in one sentence, and offers two buttons: "Open Windows settings"
(`ms-settings:easeofaccess-keyboard`) with a live re-check, and "Use Ctrl+PrtSc instead". We do
not write that registry value (D10).

### 2.6 The overlay

**One frameless, always-on-top, fullscreen `OverlayWindow` per monitor**, not one window spanning
the desktop. A spanning window has one scale factor, so mixed-DPI setups render wrong; negative
monitor origins and macOS "Displays have separate Spaces" break it outright.

Flow: trigger → capture worker grabs one `Frame` per monitor, `windows(&[])` and
`cursor_position()` **before any overlay window exists** (so our own windows never appear in the
frozen frame or the snap list) → `Event::Frames` → show windows → user selects → crop from the
frozen frame (never a second capture) → `Effect`s.

- Placement: `window.set_position(PhysicalPosition(monitor.x, monitor.y))`, `show()`, then
  `with_winit_window(|w| w.set_fullscreen(Some(Borderless(Some(handle)))))` where `handle` is the
  winit monitor whose `position()`/`size()` equals the capture `Target.bounds`. macOS uses
  `set_simple_fullscreen(true)` instead (instant, covers menu bar and Dock, no Space animation).
- HiDPI: the frame is physical pixels. The `Image` is laid out at `frame.width / scale` logical
  pixels with `image-rendering: pixelated`, so one image pixel is one device pixel. All selection
  state is in **physical desktop coordinates** in Rust (`overlay::Selection`); each window gets
  its slice converted to its own logical pixels. Conversions live in one file
  (`overlay/coords.rs`) with property tests for scale 1, 1.25, 1.5, 2, 3 and negative origins.
- A selection lives on the monitor where it started (clamped). Cross-monitor selections are out
  of scope for 0.2 (D5); "Capture screen" with all monitors covers the wide case.
- Magnifier: a second `Image` of the same source with `source-clip-*` and 8× `pixelated` zoom,
  drawn by Slint; no per-move pixel work in Rust. Rust supplies only the HUD values (cursor
  position, size, pixel colour as hex, contrast ratio) from the frame.
- Dimming outside the selection is four translucent rectangles over the image (no transparency
  needed); crosshair is two 1 px rectangles.
- Window snapping: hover highlights the top-most `Target` window under the cursor; click takes
  it; `Tab`/`Shift+Tab` cycle windows then monitors.
- Keyboard-only: arrows move the crosshair 1 px (`Shift` 10 px, `Ctrl` 50 px); `Enter`/`Space`
  sets the anchor, arrows grow the selection, `Enter` confirms; after confirm arrows nudge,
  `Shift`+arrows resize; `Esc` steps back (action bar → selection → close). Every change updates
  one live `accessible-label` ("Selection 640 by 480 at 100, 200") so a screen reader follows.
- Action bar: a row of labelled buttons inside the overlay window next to the selection
  (flips above/inside when there is no room): **C**opy (Enter, default), **S**ave, **A**nnotate,
  **T**ext, **P**in, **R**edact, s**H**are, plus Record and Scrolling when the mode allows.
  `then=` in a deep link or a "skip the action bar" setting bypasses it.
- Modes share the window: Region, Window, Screen, Scrolling, Record, ColorPicker (click copies
  hex; a second click shows WCAG contrast with AA/AAA badges), Ruler (drag shows Δx, Δy,
  distance; Enter copies).
- Delay timer: a small countdown window before the grab; repeat-last skips the overlay.

**Wayland (D3).** There is no layer-shell and the portal returns one image with no geometry.
Rule for 0.2: one monitor reported by winit → portal frame, our overlay fullscreen on it (frame
scaled to the window). Otherwise → the portal's own interactive picker
(`CaptureBackend::pick_interactive`, new, WP1), and the action bar appears on the thumbnail
window instead. Window snapping, pixel-accurate multi-monitor overlay, recording and scrolling
capture are X11/Windows/macOS only in 0.2, each with an in-place explanation.

**Performance risk (D4).** A 4K frame is 33 MB RGBA and the software renderer redraws dirty
regions on every pointer move. Budget: 16 ms per move at 3840×2160. WP2 measures this first
(Xvfb at 3840×2160 plus one real HiDPI machine). Fallback: add `renderer-femtovg` and select it
for the process when a GL context is available.

### 2.7 Other platform pieces

- **Single instance.** `main` parses args, then `Server::bind()` **before** creating any Slint
  object. `AlreadyRunning` → `launch_request(args, cwd)` → `Client::send` → exit. The handler
  re-validates links with `DeepLink::from_invoke` on the UI thread.
- **Deep links.** Windows: `HKCU\Software\Classes\tellshot` registered by the installer.
  Linux: `x-scheme-handler/tellshot` in the desktop entry (`Exec=tellshot-app %u`). macOS:
  `CFBundleURLTypes`; the URL arrives as an Apple event, which winit does not surface, so
  `platform/macos.rs` registers `kAEGetURL` and `kAEOpenDocuments` handlers with
  `NSAppleEventManager` after the loop starts (**to verify** on a Mac; D9).
- **Clipboard.** `arboard` with `image-data` and `wayland-data-control`, behind
  `trait ClipboardSink { fn set_image(&self, img: &Image) -> Result<..>; fn set_text(&self, s: &str) -> Result<..>; }`
  with `MemoryClipboard` for tests. One `Clipboard` kept alive on its own thread (X11 and Wayland
  selections die with their owner; a tray app lives long enough). GNOME Wayland has no
  data-control protocol; arboard then goes through XWayland, which works for PNG (**to verify**
  on GNOME 47+). "Copy" always puts the PNG; "Copy text" and "Copy link" put text.
- **Launch at login.** `auto-launch` 0.6 (MIT): Run key on Windows, LaunchAgent plist on macOS,
  `~/.config/autostart/*.desktop` on Linux, started with `--background` (tray only, no window).
  `autostart::{is_enabled, set_enabled}` reconcile with `general.launch_at_login` at startup.
- **Thumbnail.** `ThumbnailWindow`: frameless, always-on-top, `with_active(false)`, skip-taskbar,
  bottom-right of the captured monitor, 6 s auto-dismiss paused by hover or focus. Click or Enter
  opens the editor; buttons Copy, Save, Pin, Share, Delete. It doubles as the notification for
  errors ("Upload failed: … Retry"), so there is no notifications dependency. OS drag-out of the
  image is not possible with winit 0.30 and is deferred (D7); dragging moves the thumbnail.
- **Pins.** One `PinWindow` per pin: frameless, always-on-top, drag to move (`drag_window`),
  wheel or `+`/`-` zoom, `C` copy, `S` save, `E` edit, `Esc` close. No shadow or rounding (no
  transparency).
- **macOS activation.** `LSUIElement` in `Info.plist` and
  `with_activation_policy(Accessory)`: no Dock icon while only the tray is alive.
  `platform::macos::set_regular(bool)` (`NSApplication.setActivationPolicy`, `objc2-app-kit`, one
  `unsafe` block with a `// SAFETY:` comment) switches to Regular while an editor, library or
  settings window is open so it gets a Dock icon and Cmd+Tab, and back when the last closes.
- **Permissions.** macOS screen recording: add `tellshot_capture::permission() -> Permission` and
  `request_permission()` (CoreGraphics preflight/request; WP1). Onboarding step 1 uses them.
- **Theme.** `shell::theme::apply!(window, &settings.accessibility)` sets `Theme.high-contrast` and
  `Theme.reduce-motion` on every window and the tray at creation and on `SettingsChanged`.

### 2.8 Editor, autosave, recovery

`Session` gains `Origin { Library(ItemId), File(PathBuf), Scratch }`. Every applied edit marks the
session dirty; a 1 s debounce `slint::Timer` saves: library items through
`Library::save_project`, `.tellshot` files in place, everything else to
`<data>/recovery/<uuid>.tellshot` plus a small JSON sidecar (title, origin). Closing a window
saves synchronously and never asks. On start, leftover recovery files reopen with a status line
"Recovered after an unexpected exit". `confirm_discard` and its `rfd` dialog are deleted. Several
editor windows may be open; each has its own `Session`.

Other risks, owner in brackets:

- **Rendering changed under users** [WP6]: parley text and the new blur change pixels; `shoot
  --check` users see one round of stale images. Changelog note; no code change.
- **`ksni` + `zbus` on Linux** [WP1]: more D-Bus surface and existing `RUSTSEC` ignores for zbus 5
  split crates apply to more code. Re-run `cargo deny check`; no new ignore without a reason line.
- **X11 always-on-top and fullscreen differ per window manager** [WP2]: test under at least
  Mutter, KWin and one tiling WM (i3 or sway-XWayland); the overlay must never be left on screen:
  a 60 s watchdog and `Esc` on any overlay window close all of them.
- **Hotkey fires while the overlay is open** [WP2]: the agent ignores capture triggers while a
  flow is active, except the same trigger, which cancels (toggle behaviour, unit-tested).
- **Secrets on screen** [WP2, WP3]: findings are only ever shown through `Finding::preview()`;
  a test greps app logs and accessible labels for a seeded secret.
- **After-capture `RunCommand`** [WP2]: runs a user-configured program. Never reachable from a
  deep link (links only choose among `copy`, `save`, `edit`, `pin`), never from policy defaults
  unless the policy file itself sets it, and never through a shell.
- **One Slint compile grows** [all]: keep each `.slint` file under about 400 lines and move
  repeated pieces into `controls.slint` via WP4, so build time and review stay tolerable.
